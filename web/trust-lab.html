01 / DATA MONITORING

Synthetic reference vs current

Change a fictional catalog and observe independent quality signals. A drift alert is a reason to investigate, not proof of model failure or a command to retrain.

02 / EVALUATION INTEGRITY

Leakage test bench

Compare an event-level holdout against deliberately broken partitions. Shared review IDs, duplicate user–item pairs and future-to-past temporal contamination are separate failures.

03 / YOUR DATA / PRIVACY FIRST

Bring your own CSV — no SQL required

Use two catalog CSVs for meaningful reference-to-current drift or two interaction CSVs for train-to-test leakage. Single files receive schema, null and anomaly checks. Maximum 5 MB and 10,000 data rows per file.

04 / YOUR CATALOG / IN-BROWSER RECOMMENDATIONS

Run the recommender on your CSV

The catalog from Reference catalog CSV and the interactions from Training interactions CSV are used for local recommendations. The test interactions file is never used for ranking. User ratings of 4–5 count as positive; missing event ratings are treated as implicit interaction signals. Negative and previously viewed items are excluded. No SQL or full N×N matrix is required.

Choose a local catalog in the first CSV panel and optional training interactions in the second.

This is a bounded explanatory sandbox: up to 10,000 catalog products and 10,000 interactions, with limited history depth and neighbor exploration. Scores are uncalibrated similarities, not probabilities. Recommendation accuracy cannot be estimated without an independent held-out labeled test set.

05 / LOCAL SEMANTIC RESEARCH

Ask RecVerity

An on-device low-rank semantic retriever finds the closest project note and returns its authored explanation with a citation. No paid model, network inference, or invented answers.

Suggested topics: data leakage, drift monitoring, cold start, ranking evaluation, privacy, and authentic ratings.
